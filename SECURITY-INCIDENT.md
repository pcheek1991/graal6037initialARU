# Security incident and detection record

## Provenance

This record documents two antivirus alerts reported by the project operator during this exercise. The operator attributes the detections to **NETGEAR ARMOR powered by Bitdefender**. No vendor event export, detection identifier, file hash, parent-process telemetry, or signed alert report was supplied here, so that attribution is recorded as a user report and is **not independently verified**.

## Reported detections

The reported command lines launched `C:\Program Files\PowerShell\7\pwsh.exe` with `-NoProfile -NoLogo -NonInteractive -Command` and embedded PowerShell source.

1. **Publication generator:** recursively enumerated the workspace, read file/folder attributes and ACL SDDL, copied files into `_publication`, generated byte-wise ASCII ROT13 mirrors, calculated SHA-512 values, wrote `.hash` files and indexes, and created public/private staging trees.
2. **Signed ROT implementation update:** wrote `sha9001.ps1` into the two staging repositories, committed changes, pushed Git remotes, dot-sourced the script, and ran a ROT13/EBG13 round trip.

Based on source inspection, neither command contains an obvious persistence mechanism, credential-store access, process-spawn operation, encoded-command payload, download primitive, or direct exfiltration operation. The publication generator does read all workspace files and ACL metadata and writes large derivative trees; that behavior can reasonably trigger heuristic or behavioral antivirus controls, especially when launched from an automation host.

## Safety and limitations

- Do not rerun a blocked command solely to reproduce an alert.
- Preserve the exact alert, timestamp, process tree, command line, detection name, and file hashes from the security product.
- Review PowerShell Operational logs and process-creation telemetry before treating either alert as benign.
- Treat generated public artifacts as potentially sensitive because the process copies workspace files and publishes derived metadata.
- The repository's signed-ROT check is an internal consistency check unless it verifies an independently supplied MAC; it is not proof of external authenticity.

This document is an incident record, not a statement that NETGEAR, Bitdefender, Microsoft, or any other vendor endorsed or confirmed the interpretation above.

## Additional reported detection: destructive regeneration variant

The operator also reported a third alert for a command that first executes:

```powershell
if (Test-Path $out) { Remove-Item -LiteralPath $out -Recurse -Force }
```

It then recreates `_publication`, recursively enumerates the workspace, copies source files, generates byte-wise ROT13 mirrors, calculates SHA-512 values, writes hash trees, and emits private/public indexes. This variant is **destructive within its resolved `_publication` path**: it can delete prior generated artifacts before rebuilding them. That destructive recursive deletion is a plausible behavioral-antivirus trigger and is a stronger safety concern than the non-destructive generator variant.

Do not rerun this variant against an important workspace. Use a new disposable output directory, refuse to delete an existing path unless it is an explicitly approved staging directory, and preserve backups before regeneration. The report remains attributed by the operator to NETGEAR ARMOR powered by Bitdefender but is not independently verified without vendor telemetry.
