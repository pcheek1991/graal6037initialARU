# SHA-n and SHA-9001

## Abstract

SHA-n is a naming convention for an iterative digest construction: select a base hash and apply it repeatedly. In this archive, **SHA-9001** means SHA-1 applied exactly 9,001 times to each file: one initial application followed by 9,000 rehashes of the preceding 20-byte digest.

## Construction

For a byte string `M`, define `H_0 = M` and:

`H_i = SHA-1(H_(i-1))` for `i = 1 .. 9001`.

The recorded value is `H_9001`, encoded as lowercase hexadecimal. The output is still **160 bits**, because every SHA-1 application returns a 160-bit digest. The number 9001 describes iteration count, not digest width, key size, or cipher strength.

## Rationale and limits

Repeated hashing creates a deterministic, reproducible transformation and makes accidental changes easy to detect when the same procedure is followed. It does not turn SHA-1 into a modern collision-resistant algorithm, does not provide encryption, and does not provide 9001 bits of security. SHA-1 is cryptographically deprecated; this construction is retained here for the requested archival naming and reproducibility, not recommended for new security designs.

For new integrity systems, use a modern standard such as SHA-256, SHA-512, or SHA-3. For password storage, use a password-specific memory-hard KDF such as Argon2id rather than a general-purpose hash.

## Reproducibility

The accompanying `sha9001.py` implementation reads bytes without text conversion and applies `hashlib.sha1(...).digest()` exactly 9,001 times. The `.hash` files contain the final hexadecimal digest followed by two spaces and the relative file path. ROT13 mirrors are byte-wise transformations of ASCII letters; their SHA-9001 values are recorded independently.
